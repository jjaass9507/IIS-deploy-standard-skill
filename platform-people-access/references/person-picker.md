# 選人元件（員工選擇器）規格

所有「指定一個人」的欄位（新增使用者、主管、負責人、簽核人、指派對象、通知名單）一律用同一個元件，**不讓使用者自己打工號或姓名**。來源：power-bill-agent 的 `employee_picker`（Jinja macro＋`app.js`）與 GMS 監控平台的 `PersonPicker`（React），兩者同一規格。

現成實作：

| 前端 | 檔案 |
|---|---|
| React | `assets/frontend/PersonPicker.jsx`（`PersonPicker`、`PersonCard`、`personLabel`） |
| Jinja／Django template／純 HTML | `assets/frontend/person-picker.js`（`data-person-picker`） |
| 共用樣式 | `assets/frontend/person-picker.css`（顏色變數換成專案的 token） |

## 外觀與操作

| 項目 | 規格 |
|---|---|
| 輸入 | 單一搜尋框（放大鏡圖示），提示文字「搜尋工號 / 姓名 / 部門」；**不另設**工號、姓名、Email 輸入欄 |
| 搜尋 | 停止輸入 250 ms 後才查（debounce）；工號、姓名、Email、部門、職稱部分比對、不分大小寫；多個字詞要全部符合；`%`、`_` 視為一般字元；1 個字即可查（中文姓氏）；只回前 20 筆並提示「只列出前 20 筆，請輸入更完整的工號或姓名」 |
| 候選清單 | 搜尋框下方浮出的下拉清單（不是表格、不推擠版面）；每筆第一行**粗體姓名**＋灰色工號，第二行「部門 · 職稱 · Email」；沒有 Email 標「無 Email」 |
| 狀態 | 清單內顯示「搜尋中…」「查無符合的人員」或錯誤訊息（員工資料表無法讀取時說明原因）；舊查詢的結果晚到時丟棄 |
| 鍵盤 | ↑ ↓ 移動、Enter 選取、Esc 關閉；預設停在第一筆；沒有候選時 Enter **不送出表單** |
| 選定後 | 搜尋框顯示「姓名（工號）」並改成已選取樣式（綠框）；表單只送工號 |
| 重新輸入 | 一改字就清除已選取的人：送出的永遠是從清單選的人，不會是打出來的文字；必填時沒選就擋下並提示「請從清單選擇員工」 |
| 不可選的人 | 仍列出但淡化，第二行改寫原因（例如「無 Email，不能擔任負責人」「沒有 K18 的檢視權限」「已在名單中」），點了不會選取（`disabledReason`） |
| 多人欄位 | 「再加一位」：選定後清空搜尋框（`clearOnPick`），已選的人以人員卡列在下方（頭像字、姓名、工號、部門 · 職稱、移除鈕），並從候選中排除（`exclude`） |
| 已指定的人 | 列表與表單都用人員卡顯示，不只顯示工號；員工表查無時卡片加標籤「查無此工號」 |
| 無障礙 | `role="combobox"`／`listbox`／`option`、`aria-expanded`、`aria-activedescendant` |

## 資料來源

| 欄位性質 | 候選來源 | 例子 |
|---|---|---|
| 任何公司員工都可以 | 員工資料表（`/api/admin/employees`） | 新增平台使用者、主管、外部通知對象 |
| 必須是平台使用者 | 平台名單（業務自己的 candidates API），回傳格式相同 | 指派處理人、範圍負責人 |

React 用 `search` 屬性換來源；原生版用 `data-search-url`。

原生版的 `data-required` 是在表單 `submit` 時 `preventDefault()`。頁面自己也用 JS 攔 `submit`（例如改用 fetch 送出）時，處理器要先檢查 `if (event.defaultPrevented) return;`，或直接檢查隱藏欄位有沒有值——否則可能比元件先執行而送出空工號。後端本來就要再驗證一次。

## 頁面要一起處理的狀況

- `employee_table.configured === false`：頁面頂端警告「未設定員工資料表，只能手動輸入工號、姓名與 Email，無法核對是誰」，此時才顯示手動輸入欄位。
- `employee_table.problem` 有值（沒授權、欄位錯）：顯示原因，選人元件搜尋時也會顯示同樣的錯誤；名單照常顯示。
- 名單上某人 `directory.found === false`：標「查無此工號」，說明「權限保留不變，姓名與 Email 維持上次的資料，請確認此人是否已離職或調動」。
- 員工表的姓名／Email 和名單快照不同：提示「員工資料表的姓名或 Email 已變更，儲存後會更新」。
- 新增人員選定工號後，呼叫 `/api/admin/employees/<account>/supervisors` 預填主管，並把 `note` 顯示在主管欄位下方；管理員可以改。
